# Золотые векторы: общее поведение DSP на macOS и Windows

`scenarios.json` описывает входные сигналы (без libm: только арифметика IEEE, поэтому Swift и Rust дают одинаковые числа).
Эталон выходов (`*.f32`, little-endian float32, каждый `decimate`-й сэмпл) выгружает Swift-реализация `Sources/EvenlyDSP/Compressor.swift`:

    core/golden/gen.sh            # пересоздать эталон (нужен swiftc; результат тот же на x86_64 и arm64)

Rust-тест `cargo test` в `core/` обязан совпасть с эталоном (допуск 1e-5). Меняете DSP в Swift: пересоздайте эталон и поправьте Rust, и наоборот.

Генератор сигнала (сэмпл с номером n в потоке из interleaved-каналов, все операции в f32):
- `silence`: 0
- `tri`: p = n % period; v = 1 - 2 * |2p - period| / period (|…| и деление в f32); сэмпл = v * amp
- `noise`: на каждый сегмент своё состояние s = 12345 (u32); перед каждым сэмплом s = s * 1664525 + 1013904223 (wrapping); v = (s >> 8) / 8388608 - 1; сэмпл = v * amp
Номер n для `tri` считается внутри сегмента.
Блоки: размеры из `blocks` циклически, в сэмплах потока (для стерео: frames * channels); целевой push на блок = 0, если начало блока в [from_seconds, to_seconds) секунд (`toggle_off`), иначе mode.push. Состояние одно на весь поток (как в приложении).
